1. Présentation du projet

BudgetCollab est une application de gestion de budgets collaboratifs. Elle permet à des utilisateurs de créer des budgets personnels et partagés, d'ajouter des transactions, et de gérer des dépenses via un système de vote lorsque les montants dépassent un seuil défini.

🎯 Fonctionnalités principales
• Authentification JWT
• Budgets personnels
• Budgets partagés (membres)
• Transactions (revenus/dépenses)
• Catégories personnalisables
• Dashboard & statistiques
• Système de vote
• Notifications email
• Journal d'activité
👥 Rôles utilisateurs
Admin — Accès total, gestion des utilisateurs, approbation des transactions

User — Gère ses transactions, budgets, participe aux budgets partagés et aux votes

Pourquoi pas MVC classique ?
L'architecture choisie est une architecture en couches (Router → Service → Model), supérieure au MVC pour une API REST car elle permet de centraliser les règles métier complexes (vote, notifications, logs) dans les Services plutôt que de les disperser dans les Models. Cela simplifie les tests, la maintenance, et évite les oublis de validation.

Pourquoi cette architecture ?

CritèreArchitecture en couchesMVC classique
Règles métier complexes✅ Centralisées dans les Services❌ Dispersées dans les Models
Testabilité✅ Services testables isolément⚠️ Models couplés à la DB
Réutilisabilité✅ Un Service compose plusieurs Models❌ Limitée à un Model
Vélocité✅ Différence négligeable (~0.1ms)⚠️ Légèrement plus rapide
Sécurité✅ Validation centralisée⚠️ Risque d'oublis
Maintenabilité✅ Chaque couche a un rôle clair⚠️ Models "fourre-tout"

7. Authentification & sécurité

🔒 Mesures de sécurité implémentées

MesureDétail
Mots de passeHachés avec bcrypt (sel automatique, 12 rounds)
AuthentificationJWT (JSON Web Token) avec expiration 24h
TokensSignés avec HS256, payload contient user_id + role
Contrôle d'accèsMiddleware vérifie le token et le rôle sur chaque requête protégée
ValidationPydantic valide toutes les entrées/sorties automatiquement
CORSConfigurable via CORS_ORIGINS (.env)
SecretsJWT_SECRET, SMTP_PASSWORD dans .env — jamais dans le code
Injections SQLSQLAlchemy ORM élimine les risques d'injection

Flux d'authentification

1. POST /api/auth/login { email, password }
2. Vérification bcrypt du mot de passe
3. Génération d'un token JWT (24h)
4. Retour du token au client
5. Le client envoie le token dans l'en-tête Authorization: Bearer <token>
6. Chaque endpoint protégé vérifie le token + rôle via les dépendances FastAPI

9. Système de vote

Le système de vote est une nouveauté par rapport à l'ancienne application PHP.

Fonctionnement

1. Un utilisateur crée une transaction de type "dépense"
2. Si le montant > VOTE_THRESHOLD (500 TND par défaut) :
   → La transaction est créée avec le statut "pending"
   → Un vote est automatiquement créé
3. Les membres du budget partagé peuvent voter
4. Quand le nombre de votes "pour" atteint VOTE_APPROVAL_PERCENT (50%) :
   → La transaction est approuvée
   → Un email de confirmation est envoyé
5. Si la majorité vote "contre" :
   → La transaction est rejetée

Configuration

# Dans .env
VOTE_THRESHOLD=500.0         # Seuil en TND
VOTE_APPROVAL_PERCENT=50.0   # % de votes "pour" requis

11. Consommation par le frontend

Le backend expose une API REST pure. Le frontend (React, Vue, Angular ou autre) communique via HTTP JSON.

Exemple d'appel côté frontend

// 1. Login
const loginRes = await fetch('http://localhost:8000/api/auth/login', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ email: '...', password: '...' })
});
const { access_token, user } = await loginRes.json();

// 2. Appels protégés
const response = await fetch('http://localhost:8000/api/dashboard', {
  headers: { 'Authorization': `Bearer ${access_token}` }
});
const dashboard = await response.json();

Utilisation de Swagger

Le frontend team peut explorer et tester tous les endpoints directement depuis :

http://localhost:8000/docs

Cliquer sur "Authorize" et coller le token JWT pour tester les endpoints protégés.

CORS

Le backend est configuré pour accepter les requêtes depuis les URLs listées dans CORS_ORIGINS (`.env`).
Par défaut : http://localhost:5173 (Vite) et http://localhost:3000 (React).
